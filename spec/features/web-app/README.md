# Feature: Web App

## Summary

The Astro + TypeScript web application for reversi.sneat.games: menu, bespoke SVG board (legal-move hints, capture preview, cascading flips), classic and bidding sessions vs Bot and vs Friend, theming, PWA, standings preview and cross-promotion — the UI/session layer built on the web-game-rules engine and @sneat/game-kit.

## Problem

`web-game-rules` specifies the rules and the engine (`web/src/engine/revplay.ts`, `web/src/bot/bot.ts`), but neither knows anything about a browser, a menu, a network peer, or a screen — by design: the engine takes the player explicitly on every call and holds no turn state at all. Wave 2 needs an actual playable app: a menu that turns a choice into a match, a board people can see, read and click, two structurally different session flows (alternating classic play with forced passes vs. simultaneous hidden-bid auctions with free one-sided rounds) each playable against a bot or a friend over WebRTC, and the cross-game chrome (theme, PWA, standings preview, cross-promotion) every `@sneat/game-kit` game shares.

Two things in particular go wrong without one authoritative spec for this layer. First, **the pass**: Reversi does not alternate unconditionally, and a turn that silently skips reads as a broken game — the UI obligation around it is a product decision, not an engine detail, and lives nowhere in `web-game-rules`. Second, **bidding's asymmetric pass rule** (`web-game-rules#ac:bidding-one-sided-free-move` explicitly defers it to "a later wave's session layer") — the auction runs only when BOTH players can move, and nothing in the engine enforces that; only this layer does.

## Behavior

**Menu (`src/ui/menu.ts`).** Wraps `@sneat/game-kit`'s `renderMenu` with Reversi's options: Mode (vs Bot / vs Friend) and Variant (Classic / Bidding). Reversi has ONE board size, so the kit's third group carries a single 8 × 8 option re-titled "Board" — informative rather than a choice (a group with no checked option would silently drop the field from the submitted `FormData`). When `navigator.onLine` is `false`, vs Friend is disabled with a note and the default falls back to vs Bot; vs Bot needs no network at all.

**Board (`src/ui/board.ts`, `src/styles/board.css`).** A bespoke SVG board built from theme tokens — an accent-tinted plane, hairline grid and the four standard star points at the corners of the central 4 × 4 — deliberately not a green-felt skeuomorph. It adds four things a plain board lacks: **legal-move hints** (a translucent dot on every playable cell for the hinted side — the side to move in classic, the LOCAL player in bidding, where both sides commit against the same position); a **capture preview** that, on hover OR keyboard focus, ghosts the disc and rings every disc the move would flip; a **cascading flip** in which each flipped disc turns through its rim colour with an `animation-delay` of its Chebyshev distance from the placed disc × 40 ms (~180 ms per disc), so a capture radiates along its ray; and a **drop-in plus last-move ring** on the disc just played. At the end of a match the board dims and one soft sweep crosses it. Every cell is keyboard-reachable with a real accessible name (`"d3 — flips 3 discs"`), and all motion is behind `prefers-reduced-motion` — including the per-disc delays, which the kit's global duration override does not reach.

**Discs and player colours.** The discs are near-black and near-ivory. Rather than introduce a parallel pair of colours, the game **overrides the kit's `--p1`/`--p2` tokens**, so the score card's chips, the disc-count race bar and the game log's bid bars are automatically the same colours as the board. Because those two colours sit at opposite ends of the ramp, contrast comes from a visible **rim** on every disc, chip and bar in both themes, never from hue alone.

**Score (`src/ui/score-card.ts`).** Composes the kit's `createScoreCard` and adds a **disc-count race bar**: one horizontal track filled dark-from-the-left and light-from-the-right against the board's 64 cells, animating on every move. Reversi's score is not a tally that only grows — a single move can hand a dozen discs across — so the swing is the thing worth showing.

**Classic session (`ask-cell.ts`, `vs-bot-classic.ts`, `friend-classic.ts`).** The human (vs Bot) and the host (vs Friend) are Dark and move first. Before every move the loop asks the engine whether the side to move has a legal move; if not it **passes, loudly**: the opponent's pass is announced ("No legal moves — Bot passes" / "…your friend passes") and play continues by itself, while the local player's pass shows "You must pass" with a **Pass button that is the only enabled control in the match area** (page chrome — theme, standings — stays live). Two passes in a row or a full board end the match, and the disc count decides it, draws included. In vs-Friend a pass is sent explicitly as `{ kind: "move", turn, move: { pass: true } }` — redundant in principle, but it keeps the two message streams turn-for-turn aligned and gives the waiting player a real reason for the turn coming straight back. Every vs-Friend turn (placement AND pass) runs under a self-enforced 30 s clock (`STALL_MS`) that acts only on its OWN client, so a deadline can never desync the two boards.

**Bidding session (`ask-bid-move.ts`, `vs-bot-bidding.ts`, `friend-bidding.ts`).** A **contested** round — both players have a legal move — has both sides commit `{bid, cell}` hidden in full via `commitPayload([bid, cell], salt)`, then reveal, verify, and resolve with the kit's `resolveAuction` (higher bid wins and places; alternating tie-break; first-price TRANSFER, so the total budget is conserved). The loser's cell is discarded. A **one-sided** round — exactly one player has a legal move — runs **no auction at all**: that player simply plays, nothing is paid, the bid input is disabled, and both screens say so. When neither can move the match ends. Both clients derive which kind of round it is from the SAME position, so they always agree without negotiating it. The top-left slot stacks two cards, budgets AND disc count, because in Reversi they decide different things: the budget decides who places, the discs decide the match.

**PvP handshake (`vs-friend.ts`).** The host reserves a room (`gameId: "reversi"`), renders the invite UI BEFORE awaiting the peer (both peer helpers block until the DataChannel opens), then sends `{ kind: "hello", game: "reversi", protocol: 1, config: { mode, size: 8 } }`; the guest — who joined straight off the `#room=` link and never saw a menu — validates it and replies `hello-ack` before either side plays. A vanished peer abandons the match with an explanation the player must acknowledge; it is never resolved by guessing.

**Navigation.** `main.ts` runs the menu as a LOOP: every "Back to menu" / "Leave" returns to it, and terminal screens (abandoned match, failed connection) resolve only on acknowledgement so the menu cannot wipe them off the screen.

**Theming, PWA, cross-promotion, standings.** The kit's `theme.css` with `--accent: #16a34a`; a pre-paint inline script in `Layout.astro` applies any stored `localStorage["sneat-games-theme"]` choice before first paint, and the header's `createThemeToggle()` flips it, persisting across reloads. `@vite-pwa/astro` precaches the app shell; the service worker is registered by `main.ts` (not auto-injected) and ONLY on `*.sneat.games` — never in dev, never on a local preview, never inside a CrazyGames/itch.io iframe. The footer renders `createGamesFooter({ current: "reversi" })`. A header trophy button opens a Standings preview: a REAL local vs-Bot record kept in `localStorage` — with three buckets, because Reversi genuinely draws — plus a mocked ladder labelled "Powered by Competios — coming soon".

**Distribution.** `npm run build` produces a static `dist/` whose asset URLs are rewritten to relative paths by `scripts/relativize-dist.mjs`, so the same bundle deploys to `reversi.sneat.games` via `host-worker/` (Cloudflare Worker `reversi-game`, custom domain `reversi.sneat.games`) and zips unchanged for CrazyGames/itch.io.

## Acceptance Criteria

- `web-app#ac:menu-config`: The menu offers Mode (vs Bot / vs Friend) and Variant (Classic / Bidding), plus a single-option "Board" group for the standard 8 × 8; vs Friend is disabled with a friendly note when `navigator.onLine` is `false`, defaulting to vs Bot. Covered by `src/ui/menu.test.ts` and exercised by every e2e journey (each drives the menu to reach a match).
- `web-app#ac:board-hints`: Every cell the hinted player may legally play carries a hint dot, and the hinted player is the side to move in classic but the LOCAL player in bidding. Covered by `src/ui/board.test.ts` ("legal-move hints") and by `e2e/classic-vs-bot.spec.ts` / `e2e/bidding-vs-bot.spec.ts`, which both assert the four opening hints.
- `web-app#ac:capture-preview`: Hovering or keyboard-focusing a legal cell ghosts the disc that would land there and outlines exactly the discs that move would flip, clearing when the pointer or focus leaves. Covered by `src/ui/board.test.ts` ("capture preview") and `e2e/classic-vs-bot.spec.ts`.
- `web-app#ac:flip-cascade`: After a move, each flipped disc animates through its rim colour with a delay proportional to its distance from the placed disc, while the placed disc drops in and keeps a last-move ring. Covered by `src/ui/board.test.ts` ("flip cascade"), which asserts the per-disc `animation-delay` and the distance it is derived from.
- `web-app#ac:disc-race-bar`: The score card leads with a single bar showing the dark/light split against the board's 64 cells, updated on every move and described for screen readers. Covered by `src/ui/score-card.test.ts`.
- `web-app#ac:classic-pass-ui`: In classic mode, a player with no legal move passes — the opponent's pass is announced, and the local player's pass shows a Pass button that is the only enabled control in the match area, restoring the previous state afterwards. In vs-Friend the pass also runs under the self-enforced turn clock. Covered by `src/ui/pass-banner.test.ts` (against a CONSTRUCTED position that provably forces the pass) and end-to-end by `e2e/pvp-classic.spec.ts`'s scripted forced-pass opening, which asserts the banner on the passing side, the notice on the other, and that play continues.
- `web-app#ac:classic-journey`: A full classic vs-Bot match plays from the menu to a terminal banner naming the final disc count, with the board dimmed and swept, and the banner's outcome agreeing with the disc counts (win / loss / draw). Covered by `e2e/classic-vs-bot.spec.ts`.
- `web-app#ac:bidding-transfer`: Every contested bidding round resolves through the kit's `resolveAuction`, and the total budget across both players stays conserved (200 at `BUDGET = 100` each) from the first round to the terminal banner. Covered by `e2e/bidding-vs-bot.spec.ts` and `e2e/pvp-bidding.spec.ts` (which asserts both clients agree on the post-round budgets).
- `web-app#ac:bidding-free-move`: When exactly one player has a legal move, that player moves with NO auction and NO payment, with both screens saying so and the bid input disabled; when neither can move, the match ends. Implements `web-game-rules#ac:bidding-one-sided-free-move`. Covered end-to-end by `e2e/pvp-bidding.spec.ts`'s scripted one-sided position, which asserts the notice on both sides, the disabled bid inputs, and that both balances are unchanged across the free move.
- `web-app#ac:bidding-discs-decide`: The winner of a bidding match is decided by DISC COUNT, never by remaining budget. Covered by `e2e/bidding-vs-bot.spec.ts`, which cross-checks the terminal banner's outcome against the final disc counts.
- `web-app#ac:pvp-handshake`: A vs-Friend guest, who never saw the menu, learns the variant from the host's `hello` message and both sides proceed only after `hello-ack`; the invite UI is on screen before the peer connection is awaited. Covered by `e2e/pvp-classic.spec.ts` and `e2e/pvp-bidding.spec.ts`, which join purely via the invite link.
- `web-app#ac:pvp-agreement`: Two connected clients always end a match in agreement — the same final disc count and complementary outcomes (win/loss, or draw on both). Covered by `e2e/pvp-classic.spec.ts` and `e2e/pvp-bidding.spec.ts`.
- `web-app#ac:theme-persistence`: The theme toggle's choice persists in `localStorage["sneat-games-theme"]` across a reload, applied before first paint by `Layout.astro`'s inline script (no flash of the wrong theme), and the disc tokens resolve to distinct colours in whichever theme is active. Covered by `e2e/theme-toggle.spec.ts`.
- `web-app#ac:disc-contrast`: The disc colours are the kit's `--p1`/`--p2`, overridden by this game, so score card, race bar and log bars match the board; every disc, chip and bar carries a visible rim in both themes. Covered by `src/styles/board.css`'s token block and the rim rules, plus `e2e/theme-toggle.spec.ts`'s token assertion; the visual result itself is not machine-checkable.
- `web-app#ac:reduced-motion`: All board motion is disabled under `prefers-reduced-motion`, including the flip cascade's per-disc `animation-delay`, which the kit's global duration override does not reach. Covered by the media block in `src/styles/board.css`; **not covered by an automated test** — asserting a computed animation under an emulated media feature would test the browser, not the app.
- `web-app#ac:standings-preview`: The header trophy opens a panel showing a REAL local vs-Bot record with wins, losses AND draws (this device only) plus a mocked ladder labelled "Powered by Competios — coming soon". Covered by `src/ui/standings.test.ts` and `e2e/theme-toggle.spec.ts`.
- `web-app#ac:cross-promo`: The footer renders `createGamesFooter({ current: "reversi" })`, linking every other kit game plus the sneat.games landing page and never itself. Covered by `e2e/theme-toggle.spec.ts`.
- `web-app#ac:pwa-offline-vs-bot`: The app is an installable PWA (manifest + committed 192/512 icons); the service worker registers only on `*.sneat.games` — never in dev, on a local preview, or inside a CrazyGames/itch.io iframe — and vs-Bot needs no network by construction. **Not covered by an e2e test**: asserting true offline behaviour needs a deployed origin with the worker actually installed and the network then cut, which is out of scope for this suite; verified manually per `web/README.md`'s deploy notes.
- `web-app#ac:portal-zip`: `npm run build` produces a static `dist/` with only relative asset paths (Astro emits root-absolute ones; `scripts/relativize-dist.mjs` rewrites them post-build), deployable unmodified to `reversi.sneat.games` via `host-worker/` (worker `reversi-game`) and zippable for CrazyGames/itch.io. Covered by `npm run build` in `.github/workflows/web-ci.yml`; the zip step itself is a manual release action.
